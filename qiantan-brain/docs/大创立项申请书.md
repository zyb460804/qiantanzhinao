## 二、项目摘要（300-500 字）

菜市场小微商户（摊主）长期面临"手脏眼忙嘴快"的高强度作业环境，传统的纸笔记账、大脑记忆式经营方式难以应对进货、库存、销售、损耗等多维度信息的实时管理，导致利润核算不准、临期损耗高、采购决策凭经验。现有数字化工具多为大型连锁商超设计，功能复杂、学习成本高，难以适配摊主群体的使用能力与场景约束。

本项目研究并实现一套面向菜市场小微商户的 AI 多模态智能经营辅助系统，融合**语音识别（含方言）、视觉识别、文字解析**三种输入模态，覆盖"采购—库存—销售—分析—建议"全经营链路。系统采用"微信小程序 + FastAPI 后端 + 边缘端推理"的云边协同架构，针对菜市场弱网、低算力、多方言的真实约束，设计了离线优先的请求容错机制与边缘-云分级推理方案。

项目以技术可行性验证为核心目标，通过文献调研、问卷调查、原型实现与可用性测试相结合的研究方法，验证 AI 多模态技术下沉到小微商户场景的工程可行性与实际效用，为数字农贸、小微商户数字化转型提供技术参考。

**关键词**：小微商户；多模态交互；语音识别；计算机视觉；数字孪生；云边协同

## 三、立项背景与意义

### 3.1 选题来源

项目源于对菜市场这一典型传统零售场景的长期观察：摊主普遍依赖经验与纸笔经营，数字化程度极低，而市面现有工具均面向连锁商超或中型零售，存在明显的市场空白。团队在前期技术调研与原型探索中，发现 AI 多模态技术（语音、视觉、自然语言理解）的成熟为解决该问题提供了新的技术可能。

### 3.2 研究背景

**行业现状**：根据商务部《关于推进商品市场高质量发展的意见》及多地"数字农贸"改造政策，传统农贸市场的数字化升级正成为城市治理与民生工程的重要方向。然而当前数字化改造多聚焦于市场管理端（如溯源秤、信息公示屏），面向**摊主个体经营**的轻量化工具严重缺位。

**用户痛点**（基于前期桌面调研与观察）：
- **记账难**：摊主双手沾水沾油，频繁洗手不便操作手机触摸屏
- **核算乱**：进货、销售、损耗、赊账等多本"糊涂账"，月底算不清利润
- **损耗高**：临期商品缺乏提醒，蔬菜损耗率可达 10-20%
- **决策盲**：补货凭经验，受天气、节气、客流波动影响大却无法量化
- **方言障碍**：中老年摊主普通话不标准，通用语音识别准确率低

### 3.3 研究意义

**理论意义**：探索 AI 多模态融合技术在低门槛、高约束（弱网、低算力、多方言、低数字素养用户）场景下的适用性与工程方法，丰富人机交互在垂直民生领域的应用研究。

**实际价值**：
- 为菜市场摊主提供贴合作业习惯的轻量化经营工具
- 为"数字农贸"政策落地提供摊主侧的技术补充
- 为同类小微零售场景（夜市、早市、流动摊贩）提供可复用的技术方案

## 四、国内外研究现状

### 4.1 智能记账与经营管理系统

国内外主流记账与 ERP 工具（如用友、金蝶、记流水类 App）多面向中小企业或个人生活记账，**功能重、学习成本高**，且不支持语音/视觉等多模态输入，难以适应摊主的作业场景。

### 4.2 语音识别与方言适配

通用语音识别（讯飞、百度、腾讯）在普通话场景下准确率已超 95%，但**方言场景仍是难点**。讯飞等厂商提供了部分方言模型（粤语、四川话等），但在垂直领域的工程化适配研究较少。

### 4.3 商品视觉识别

基于深度学习的商品识别（YOLO 系列、ResNet 等）在零售货架场景已有较多研究，但**面向生鲜散装商品（形态不规则、遮挡严重）的轻量化端侧识别**仍是开放问题。

### 4.4 数字孪生与时序预测

数字孪生与 Prophet、LSTM 等时序预测技术已在工业、供应链领域成熟应用，但**下沉到小微商户经营场景的研究极少**——这是本项目的切入空白。

### 4.5 现有方案对比

| 维度 | 通用记账App | 中小企业ERP | 本项目 |
|---|---|---|---|
| 目标用户 | 个人生活 | 中小企业 | 菜市场摊主 |
| 输入方式 | 触屏为主 | 触屏+PC | 语音+视觉+文字 |
| 方言支持 | 无 | 无 | 粤语/四川话/上海话 |
| 弱网容错 | 无 | 弱 | 离线队列+幂等 |
| 部署形态 | 纯云 | 纯云 | 云边协同 |
| 经营建议 | 无 | 无 | 数据驱动 AI 建议 |

## 五、研究目标与内容

### 5.1 研究目标

1. 研究 AI 多模态技术在小微商户高约束场景下的**适用性与工程可行性**
2. 设计并实现一套覆盖经营全链路的**智能经营辅助原型系统**
3. 通过原型验证系统在弱网、低算力、多方言约束下的**工程表现**
4. 形成可复用的技术方案与**研究方法体系**

### 5.2 研究内容（子课题）

**子课题 1：小微商户经营场景调研与需求建模**
- 通过文献研究、问卷调查、观察法，建立摊主典型作业流程模型与痛点图谱
- 产出：需求规格说明书、用户画像

**子课题 2：多模态经营记录引擎**
- 语音输入（ASR + 方言适配）+ 视觉识别（YOLO 端侧/云端）+ 文字自然语言解析
- 三种模态统一归一到结构化经营事件（进货/销售/损耗）
- 产出：多模态解析引擎、语义理解算法

**子课题 3：库存数字孪生与批次生命周期管理**
- 基于进货/销售事件构建库存实时镜像
- 批次 FIFO 消耗、临期预警、保质期生命周期管理
- 产出：数字孪生模型、批次管理算法

**子课题 4：基于时序预测的智能采购建议**
- 基于 Prophet 的销量预测，结合天气、节气、周末等多源信号
- 输出可执行的采购清单建议
- 产出：预测模型、建议生成算法

**子课题 5：云边协同架构与弱网容错**
- 边缘端（智能秤/价目屏）预计算 + 云端精算的分级推理
- 离线优先的请求容错（幂等键、自动同步、指数退避）
- 产出：云边协同框架、容错中间件

**子课题 6：系统集成与可用性验证**
- 原型系统集成、性能测试、团队内可用性测试
- 产出：测试报告、可用性评估报告

### 6.1 研究方法

| 阶段 | 方法 | 产出 |

| 需求研究 | 文献研究法 + 问卷调查法 + 观察法 | 调研报告、需求文档 |

| 效果验证 | 实验测试法 + 可用性评估 | 测试报告、评估报告 |

### 6.2 技术路线图

```
需求调研 ─→ 架构设计 ─→ 核心模块实现 ─→ 算法模型训练 ─→ 系统集成 ─→ 测试验证 ─→ 结题
  │            │            │               │              │            │
  ▼            ▼            ▼               ▼              ▼            ▼
问卷+文献   云边协同     多模态引擎      YOLO/Prophet    全链路      性能+可用性
            分层架构     +数字孪生       +方言ASR        闭环        测试报告
```

### 6.3 关键技术方案

**总体架构**（详见架构总览图）：

- **前端**：微信小程序原生（ES5），24 个核心页面，设计系统统一
- **后端**：Python 3.13 + FastAPI + SQLAlchemy(async) + PostgreSQL/SQLite + Alembic 迁移
- **AI/ML**：讯飞 ASR（WebSocket）、YOLOv8（ONNX 端侧推理）、Prophet（销量预测）
- **边缘**：Python 边缘模块（视觉推理、称重数据采集、OTA、心跳）
- **基础设施**：Docker Compose、CI（GitHub Actions）、Prometheus 监控、Sentry 错误追踪

**关键技术难点与解决方案**：

1. **多模态语义归一**：三种输入（语音/视觉/文字）解析为统一的结构化经营事件，通过自研语义解析器实现字段抽取与置信度评估
2. **弱网容错**：基于 Idempotency-Key 的写请求幂等 + 客户端离线队列 + 网络恢复自动同步
3. **多租户安全**：JWT 强制 token 鉴权 + TenantContext ContextVar 中间件 + 生产环境启动自检（fail-closed）
4. **端侧视觉推理**：边缘端预计算检测结果，云端仅做精算与业务处理，降低延迟与带宽

## 七、创新点（重点章节）

> 📌 大创评审核心关注。本项目创新点均有代码实现作为可行性证据。

### 创新点 1：面向"手脏眼忙"场景的多模态经营记录融合

将语音（含方言）、视觉、文字三种输入模态统一到一个记账流水线，适配摊主无法频繁触屏的真实作业约束。**区别于现有工具的单一触屏输入模式**，属应用场景创新。

**可行性证据**：已实现 voice（语音/文字双模态）+ vision（拍照识货）三入口归一到统一解析引擎（参见 `backend/app/routers/voice.py`、`vision.py`）。

### 创新点 2：边缘-云协同的分级视觉推理架构

设计"边缘端预计算 → 云端精算 → 演示兜底"的三级推理模式，解决小程序端算力不足又要实时识别的矛盾，同时兼容无硬件部署的演示场景。属架构创新。

**可行性证据**：`backend/app/routers/vision.py` 的 recognize 接口已实现 edge/demo/placeholder 三模式自动切换。

### 创新点 3：方言感知的语音识别工程化适配

针对摊主群体普通话不标准的现实，研究并实现了方言（粤语、四川话、上海话）到通用 ASR 模型的映射与降级策略，填补垂直场景的方言工程化空白。属工程方法创新。

**可行性证据**：`backend/app/services/asr_iflytek.py` 的 DIALECT_MAP 实现方言到讯飞 pd 参数的映射，含未知方言的优雅降级。

### 创新点 4：库存数字孪生与批次 FIFO 生命周期管理

将企业级的数字孪生思想下沉到小微场景，基于进货/销售事件实时构建库存镜像，并通过批次 FIFO 消耗算法实现临期预警与损耗归因。属方法创新。

**可行性证据**：`backend/app/routers/twin.py`（数字孪生接口）+ `backend/app/services/batch.py`（批次 FIFO 消耗与回滚）。

### 创新点 5：离线优先 + 幂等的弱网容错机制

针对菜市场网络不稳定的真实约束，设计了"客户端离线队列 + 幂等键中间件 + 指数退避重试 + 网络恢复自动同步"的完整容错链路，支持 POS 订单、语音草稿的离线保存与恢复。属工程创新。

**可行性证据**：`backend/app/core/idempotency_middleware.py` + `miniprogram/utils/offline-sync.js` + `miniprogram/app.js` 的请求层封装。

### 创新点 6：数据驱动的智能采购建议

融合销量历史（Prophet 时序预测）、天气信号、节气信息、周末效应等多源数据，生成可执行的采购清单建议，并支持"保守/标准/激进"三方案沙盘对比。属方法创新。

**可行性证据**：`backend/app/routers/advice.py`（每日建议+模拟）+ `ml/prophet_predict.py`（销量预测）+ `miniprogram/pages/sandbox`（决策沙盘）。
