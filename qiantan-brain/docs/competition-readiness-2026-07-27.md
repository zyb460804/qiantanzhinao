## 1. 必须先直面的三个判断

这三条是从 39 份文档与代码逐行核实中得出的，**任何一条不处理都会在答辩中被打穿**。

### 判断 1：模型是空的

- 全仓库**零个** `.pt`/`.onnx`/`.tflite` 权重文件，`train_yolo.py` 从未执行过
- `datasets/products/` 的 600 张图是 Pillow 画的**彩色矩形**（640×640 灰底，每类换色，标签坐标 600 张完全相同 `0.5 0.5 0.4 0.4`），`datasets/products/README.md` 四处自警「不具备任何真实识别能力，切勿上生产」
- `edge/vision/inference.py` 的 `_demo_predict` 按图片前 1024 字节求和当随机种子、random 挑 1-3 个类别 —— **演示时看到的「白菜 0.92」是编的**
- `backend/app/services/forecast.py` 的 Prophet 分支**从未执行**：实测 `import prophet` 报 ModuleNotFoundError 且未在 requirements 声明，每次都静默回落到 moving_average；即使装上，`df['temp']` 整列赋同一个常数（零方差回归变量），数学上无效，且界面取了不存在的列名 → 界面上的「温度回归 0.00」恒为零
- 立项书第 11.1 节「ML 2500+ 张标注数据集」与 `datasets/README` 自陈的 600 张占位图直接矛盾 —— **两者不可同时提交**

### 判断 2：用户数据是零

- `用户调研问卷.md` 设计精良（22 题、五段式、附分析指引），但目标是「未来收集 50-100 份」，**仓库内 0 份回收、0 份统计**
- `摊主故事包.md` 里的老张（52 岁）、王姐（45 岁）、刘哥（48 岁）**全是虚构人物**，文档第 17 行自陈「真实数据指 seed_enhanced.py 生成的演示库」——「损耗从 18% 降到 6%」是故事设定而非实测
- `experiment-report.md` 首行写着「状态：待实地采集」，第 4 节是 `X% → Y%` 空槽
- README 与项目介绍里「降低损耗 5-10 个百分点」「采纳率 0.65」**全部无实测依据**，0.65 是种子演示数据的取值

### 判断 3：四个最大算法模块在产品里调不到

grep 全 `app/` 确认零引用：
- `anomaly_detector.py`（755 行，7 检测器）—— 只被测试导入；且有**已确认 bug**：`ensemble_vote_threshold=2` 要求同类型 ≥2 票，但 ZERO_SALES / DATA_ERROR / PATTERN_SHIFT 各只有 1 个检测器产出 → 永远凑不满 2 票被静默丢弃，实测 `quick_check([12,10,11,0,0,0], 0.0).by_type` 返回空 `{}`
- `supplier_scorer.py`（682 行，QCOS 五维评分）—— 零引用
- `dynamic_pricing.py`（588 行，四种降价策略）—— 零引用
- `inventory_optimizer.py` 的报童模型三个函数 —— 只被测试导入；advisor 只用了其中的 `calc_safety_stock` / `calc_reorder_point` / `_estimate_waste_percentage`

合计约 2270 行代码 + 报童模型，**产品里点不出来**。评委说「演示一下供应商评分」就没有然后了。

### 大创（教育部 2019《管理办法》+ 多校共性）

**关键事实**：教育部层面**并未规定结题必须产出论文/专利/软著**，成果门槛下放到各校自定。但多校共性是「择一即可」的清单制：论文 / 专利 / **软著** / 实物+视频 / 竞赛获奖 / 调研报告 任一项即可结题。

**软著是软件类大创最快、最可控的硬成果**：
- 登记制非审稿制（不依赖期刊 3-6 个月审稿运气，不像发明专利要 1-3 年实审）
- 普通办理约 30 个工作日出证，线上全流程 40-45 个工作日（约 2-3 个自然月）
- 2017 年后普通登记**已免费**，加急需付费（5 工作日约 6800 元、26-30 工作日约 3000 元）
- 唯一登记机构：中国版权保护中心 ccopyright.com.cn

**立项申请书两个具体风险**（我读了该文件）：
- 第 226 行把软著申请排在**第 12 月（与结题同期）** —— 按普通办理 40-45 工作日算**必然赶不上结题**，应提前到第 8-9 月
- 第 254 行软著预算 300-500 元 —— 普通已免费、能压进 1 个月的加急要 3000 元起，预算数字与真实费用不符
- 第 237 行「软著 1-2 项」+ 第 241 行「论文 1 篇（争取）」的**主次排序是对的**，保持

**结题答辩硬失分点**：目标完成度对照（与立项书逐条比对）、成果无第三方可核验凭证（只有截图自述）、过程留痕缺失（季度/中期报告临时补）、答辩答不出「这项工作具体是谁做的」「核心算法原理是什么」。

### 计设（调研失败，凭已知常识补）

计设由中国高等教育学会主办，分类较细（软件应用与开发、人工智能应用、大数据等），软件类常看重：选题价值、创新性、技术难度与工作量、作品完整度（可运行）、文档规范（作品说明书 + 源码 + 演示视频）。**以下三条是计设的常识性要点，置信度低于 iCAN/大创，正式备赛前请去 jsjds.cn 核对当年细则**：

- 软件类须提交可运行作品 + 作品说明书 + 源码 + 演示视频，软件应用与开发类对**原创性与工作量**最敏感
- 计设允许同主题作品参加其他竞赛（区别于 iCAN 的不重复参赛）
- 计设评审看「完整可用」重于「功能多」—— 半成品是大忌

### P2 —— 锦上添花

#### P2-1 商业计划书（iCAN 创业赛道核心，创新赛道也考商业模式可行性）

- **现状**：README 列为成员C 产出，仓库内无此文件

#### P2-2 差分隐私的 ε 口径修正

- **现状**：无组合会计却每次报 `privacy.epsilon = 1.0`；噪声源是 stdlib random（非密码学安全 PRNG）；sensitivity 是拍定常数

- **意义**：被懂数学的评委追问「你们的 ε 是怎么算的」时的防御工事

#### P2-3 文档大整理：剔除过时件、保留诚实件

## 6. 一个反模式警告

**不要做的事**：继续在文档里加新功能描述、继续写「已实现联邦学习/数字孪生/大模型」这类技术名词、继续把演示数据当真实数据引用。

**为什么**：项目目前的强项是「工程体量 + 文档密度 + 测试覆盖 + 算法实现真实存在于代码」，弱项是「叙事—代码—演示」断层。继续往叙事侧加内容会**拉大断层**，而不是缩小。所有提升工作都应该往**代码可演示性**与**真实用户/数据**两端投入，而不是往叙事侧投入。

最短路径：**先用 1 周把 P0 全部修掉（含安全审计两项）+ 跑通合成数据训练 + 接一个算法 API 出来**，这三件事把项目从「叙事漂亮但一问就倒」翻成「叙事克制但能现场演示」—— 这是质变。
